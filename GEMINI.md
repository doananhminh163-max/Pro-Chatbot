# GEMINI.md - Pro Chatbot Context

This document provides foundational context and instructions for AI agents working on the **Pro Chatbot** project.

## Project Overview
Pro Chatbot is a full-stack application designed for document analysis and AI interaction using specialized CLI tools (Gemini CLI, Opencode CLI). It features a robust multi-user system with session-based chat history and advanced document management.

### Tech Stack
- **Backend:** Node.js, Express, TypeScript, Prisma (ORM with SQLite), Multer (File uploads).
- **Frontend:** React, Vite, TypeScript, Material UI (MUI), SCSS.
- **AI Execution:** CLI-based execution via `spawn` with PowerShell wrapping for Windows safety.

## Architecture
The project is split into a `backend` and a `frontend` directory.

### Backend Structure (`/backend`)
- `src/controllers/`: Handles API requests and responses.
- `src/services/`: Contains core business logic (Chat logic, CLI execution, Document handling).
- `src/routes/`: Express route definitions.
- `src/config/`: Environment configurations (`env.ts`), Passport (Auth), and Prisma client.
- `prisma/`: Database schema (`schema.prisma`) and migrations.

### Frontend Structure (`/frontend`)
- `src/pages/`: Page-level components (Admin, Client, Public).
- `src/components/`: Reusable UI elements.
- `src/services/`: API client functions (using Axios).
- `src/contexts/`: Global state management (Auth, Theme).

## Core Mechanisms

### 1. Document Storage (Mandatory Rule)
Files must be stored using a strict hierarchy based on user and session IDs to maintain privacy and organization.
- **Root Directory:** Defined by `USER_DOCS_ROOT` in `.env` (Default: `D:\Projects\user_docs`).
- **Hierarchy:** `{USER_DOCS_ROOT}/{userId}/{sessionId}/{filename}`.
- **Initial Upload:** Files uploaded without a `sessionId` (e.g., first message or from Documents page) are saved directly in `{USER_DOCS_ROOT}/{userId}/`.
- **Linking & Moving:** When a message is sent, the system MUST physically move files from the user root to the specific `{sessionId}` folder and update the `filePath` in the Database. Empty legacy `general` folders should be cleaned up.

### 2. Chat Execution
- AI replies are generated by calling external CLI tools.
- Commands are wrapped in PowerShell on Windows to handle complex prompts and line breaks safely.
- Documents are passed to the CLI via pipes (`Get-Content -Path ... -Raw | ...`).

## Building and Running

### Root Level
- `npm run install:all`: Install dependencies for both backend and frontend.
- `npm run dev`: Start both backend and frontend concurrently.

### Backend
- `npm run dev`: Start the development server (tsx watch).
- `npm run build`: Compile TypeScript to JavaScript.
- `npx prisma migrate dev`: Apply database migrations.

### Frontend
- `npm run dev`: Start the Vite dev server.
- `npm run build`: Build for production.

## Development Conventions
- **Surgical Changes:** Modify only the code necessary for the task. Match existing style and formatting.
- **Type Safety:** Ensure all new code is properly typed in TypeScript. Avoid `any`.
- **Prisma usage:** Always include necessary relations (e.g., `include: { documents: true }`) when fetching chat sessions or messages to ensure the UI displays attachments correctly.
- **File Uploads:** In `FormData`, always append fields like `sessionId` *before* the `file` to ensure they are available to Multer's storage engine.

## Key Files to Watch
- `backend/prisma/schema.prisma`: The source of truth for the data model.
- `backend/src/services/chat.service.ts`: The core logic for AI interaction and session management.
- `backend/src/controllers/document.controller.ts`: Handles file uploads and storage path resolution.
- `frontend/src/pages/client/ChatPage.tsx`: The main user interface for the AI agent.
